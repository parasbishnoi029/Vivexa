# Docs/11_Python_Coding_Standards.md

# AI Data Analytics Platform

## Python Coding Standards

Version: 1.0

Priority: Mandatory

---

# 1. Purpose

This document defines the Python coding standards for the project.

Every Python file must follow these rules.

Applies to:

- Backend
- Analytics Engine
- AI Engine
- Machine Learning
- Reports
- Security
- Utilities

---

# 2. Python Version

Python 3.12+

Never support outdated versions unless absolutely required.

---

# 3. General Philosophy

Python code should be:

Simple

Readable

Modular

Reusable

Well documented

Testable

Fast

Secure

---

# 4. Code Organization

Each module should have one responsibility.

Good

analytics/

forecasting/

statistics/

reports/

security/

database/

Bad

utils.py

helpers.py

common.py

(These become dumping grounds.)

---

# 5. File Size

Recommended

<300 lines

Maximum

500 lines

If larger

Split into modules.

---

# 6. Function Rules

Functions should

Do one thing

Return one responsibility

Avoid side effects

Example

Good

calculate_statistics()

Bad

calculate_statistics_and_generate_pdf()

---

# 7. Type Hints

Required everywhere.

Example

def analyze_dataset(
    dataset: DataFrame
) -> AnalysisResult:

No untyped functions.

---

# 8. Docstrings

Every public function

Every class

Every module

Must include

Purpose

Parameters

Returns

Raises

---

# 9. Variable Naming

Good

dataset

forecast

customer_age

monthly_revenue

Bad

x

a

temp

data1

---

# 10. Constants

Never hardcode.

Create

constants.py

Example

MAX_UPLOAD_SIZE

SUPPORTED_FILE_TYPES

DEFAULT_TIMEOUT

---

# 11. Exceptions

Never use

except:

Always

except ValueError

except FileNotFoundError

etc.

---

# 12. Logging

Never use print()

Always

logging

Different levels

INFO

WARNING

ERROR

CRITICAL

DEBUG

---

# 13. Configuration

Everything configurable.

Never hardcode

API keys

Database URLs

Model names

Storage paths

Use

.env

---

# 14. Imports

Standard Library

↓

Third Party

↓

Project Imports

Alphabetically sorted.

---

# 15. Async

Use async only when it improves performance.

Avoid unnecessary complexity.

---

# 16. Data Processing

Preferred Order

Polars

↓

DuckDB

↓

Pandas (only if required)

---

# 17. Machine Learning

Separate

training/

prediction/

evaluation/

Never mix everything into one script.

---

# 18. AI

Prompt templates

Separate folder.

Never hardcode prompts inside Python.

---

# 19. Testing

Every important module

Unit tests

Integration tests

Performance tests (later)

---

# 20. Code Review Checklist

Readable?

Typed?

Documented?

Logged?

Secure?

Efficient?

Tested?

---

# 21. Folder Structure

backend/

analytics/

ai/

database/

reports/

security/

storage/

tests/

utils/

# 22. Forbidden

No global variables.

No duplicated code.

No secrets.

No huge files.

No commented-out dead code.

No unused imports.
