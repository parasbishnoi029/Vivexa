# Docs/02.5_Technology_Stack_and_Tool_Selection.md

# AI Data Analytics Platform

## Technology Stack & Tool Selection

Version: 1.0

---

# 1. Purpose

This document explains why every major technology used in the project was selected.

The goal is to avoid random technology choices and maintain consistency throughout development.

Every technology should satisfy at least one of these conditions:

- Free or generous free tier
- Production-ready
- Large community
- Easy to maintain
- High performance
- Scalable

---

# 2. Project Philosophy

The platform is built around one idea:

> Python performs analytics.
>
> AI performs reasoning.
>
> The frontend presents results.

This separation keeps the platform accurate, scalable, and easier to maintain.

---

# 3. Frontend

Selected:

Next.js

Reason

- Excellent React framework
- Fast
- SEO friendly
- Easy deployment
- Great developer experience
- Large community

Alternatives Considered

React + Vite

Reason not selected

Missing built-in routing and production features.

Angular

Reason not selected

Too heavy for this project.

Vue

Reason not selected

Smaller ecosystem for our requirements.

Decision

Next.js

---

# 4. Backend

Selected

FastAPI

Reason

- Built for Python
- Very fast
- Automatic API documentation
- Easy validation
- Async support
- Excellent for AI projects

Alternatives

Flask

Reason not selected

Too much manual setup.

Django

Reason not selected

Excellent framework but unnecessary for our API-first architecture.

Decision

FastAPI

---

# 5. Programming Language

Selected

Python

Reason

Almost every analytics and machine learning library is available.

Libraries include

- Polars
- Pandas
- NumPy
- SciPy
- Statsmodels
- scikit-learn
- Plotly
- DuckDB

Decision

Python will contain all analytics logic.

---

# 6. Database

Selected

PostgreSQL

Reason

- Reliable
- Production ready
- Strong SQL support
- Excellent performance
- Works with Supabase

Decision

PostgreSQL

---

# 7. Authentication

Selected

Supabase Auth

Reason

- Email login

- Email verification
- Secure session handling

Decision

Supabase Auth

---

# 8. File Storage

Selected

Supabase Storage

Reason

- Free tier
- Easy integration
- Secure access
- Good enough for MVP

Future

AWS S3 if required.

---

# 9. Analytics Library

Primary

Polars

Reason

- Faster than Pandas for many workloads
- Lower memory usage
- Modern API

Secondary

Pandas

Reason

Some libraries still expect Pandas DataFrames.

Decision

Use Polars by default and convert to Pandas only when necessary.

---

# 10. SQL Engine

Selected

DuckDB

Reason

- Extremely fast
- Excellent for analytics
- Reads CSV, Parquet, and other formats directly
- Embedded (no server needed)

Decision

DuckDB

---

# 11. Machine Learning

Selected

Reason

Stable and widely used.

# 15. Free vs Paid Strategy

Current Budget

₹0

However,

Never reduce analytics quality simply to save money.

---

# 16. Technology Rules

Python performs calculations.

AI explains calculations.

Frontend never performs business logic.

Database never stores secrets.

Authentication never bypasses security.

Every module should be replaceable.
